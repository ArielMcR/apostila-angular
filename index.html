Angular

Guia prático do iniciante

Este é um guia introdutório sobre o desenvolvimento para Web com TypeScript e o framework Angular (versão 17, compatível com Node.js 18 — usada no laboratório do curso). O material foi pensado para um minicurso de aproximadamente 3 horas, com foco em um CRUD completo, para pessoas que estão tendo o primeiro contato com o framework.

Como usar este material
Ao longo do guia, blocos como este trazem links da documentação oficial do Angular (https://angular.dev) para você se aprofundar em cada assunto. Todo o código foi escrito no padrão atual do Angular: componentes standalone, signals e o novo control flow (@if, @for).
Sobre versões: este guia usa Angular 17, que roda com Node.js 18 (o que está instalado nas máquinas do laboratório). O Angular 17 já traz tudo que o curso usa: componentes standalone, signals e o control flow @if/@for. Se a turma tivesse uma versão mais antiga (15/16), alguns trechos mudam (NgModules e *ngIf/*ngFor).

Preparando o ambiente e o projeto

🎯 MISSÃO 01 — COLOCAR O ANGULAR PARA RODAR

Ao final deste módulo, você terá um projeto Angular criado, executando no navegador e entenderá onde ficam os arquivos principais.

🎯 Objetivo⏱️ 30 min

O que é o Angular e por que usá-lo

O Angular é um framework para construção de aplicações web mantido pelo Google. Ele é escrito em TypeScript (JavaScript com tipagem) e serve principalmente para criar SPAs (Single Page Applications) — aplicações que carregam uma vez e atualizam a tela dinamicamente, sem recarregar a página inteira a cada clique.

A ideia central do Angular é dividir a interface em componentes reutilizáveis. Cada componente combina três coisas: a lógica (TypeScript), o visual (um template HTML) e o estilo (CSS). Além disso, o framework já traz "de fábrica" solução para roteamento, requisições HTTP, formulários e injeção de dependência, o que evita ter que escolher e juntar várias bibliotecas separadas.

Comparado a alternativas como React e Vue, o Angular é considerado mais "opinativo": ele impõe uma estrutura e um jeito de fazer as coisas. Isso tende a facilitar a manutenção em projetos grandes e em times, porque todo mundo segue o mesmo padrão.

Pré-requisitos e instalação

Antes de tudo, é preciso ter o Node.js instalado (que já traz o npm, o gerenciador de pacotes). Você pode conferir se já tem tudo instalado rodando no terminal:

node --version
npm --version

Com o Node.js pronto, instale o Angular CLI globalmente. A CLI (Command Line Interface) é a ferramenta de linha de comando que cria projetos, gera componentes, roda o servidor de desenvolvimento e faz o build da aplicação.

npm install -g @angular/cli@17

Para verificar a instalação e a versão instalada:

ng version
Documentação
Guia de instalação e primeiros passos: https://angular.dev/installation

Criar e rodar um projeto

Para criar um novo projeto, use o comando ng new seguido do nome do projeto. No caso deste guia, vamos chamar de "agenda" (uma pequena agenda de contatos que usaremos como exemplo no CRUD).

ng new agenda

Se a CLI global reclamar da versão do Node, crie o projeto sem depender da instalação global: npx @angular/cli@17 new agenda.

A CLI vai fazer algumas perguntas: qual formato de folha de estilo usar (escolha CSS para simplificar) e se deseja habilitar SSR/SSG (renderização no servidor — pode responder No para um minicurso). Depois disso, ela cria a estrutura de pastas e já instala tudo automaticamente.

Entre na pasta do projeto e inicie o servidor de desenvolvimento:

cd agenda
ng serve

Pronto! Agora acesse http://localhost:4200/ no navegador para ver o projeto rodando. O servidor tem live reload: sempre que você salva um arquivo, a página recarrega sozinha com as mudanças.

Dica
Se quiser que a CLI não pergunte nada e já abra o navegador, use: ng new agenda --style=css --ssr=false (ou npx @angular/cli@17 new agenda --style=css --ssr=false) e depois ng serve --open (o --open ou -o abre o navegador automaticamente).

Anatomia dos arquivos do projeto

Ao criar o projeto, o Angular gera vários arquivos e pastas. Nem tudo importa agora, então vamos aos que realmente interessam neste momento:

Arquivo / pastaPara que serve
src/main.tsPonto de entrada da aplicação. É ele que "liga" (faz o bootstrap) do componente raiz.
src/index.htmlA única página HTML de verdade. É onde o Angular injeta a aplicação.
src/app/app.config.tsOnde ficam os providers globais (rotas, HttpClient, etc). Substitui o antigo AppModule.
src/app/app.routes.tsOnde declaramos as rotas da aplicação.
src/app/app.tsO componente raiz (lógica em TypeScript). Em versões antigas: app.component.ts.
src/app/app.htmlTemplate (HTML) do componente raiz.
src/app/app.cssEstilos do componente raiz.
angular.jsonConfiguração geral do projeto (build, assets, etc).
package.jsonLista de dependências e scripts do projeto (como npm start).
Atenção à nomenclatura entre versões. No Angular 17 (usado neste guia) os arquivos do componente raiz se chamam app.component.ts, app.component.html e app.component.css. A partir do Angular 20 eles passaram a se chamar app.ts, app.html e app.css. O conteúdo é equivalente; muda só o nome do arquivo.

Vamos abrir o src/app/app.ts para entender a estrutura mínima de um componente. Ele é mais ou menos assim:

import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {
  // A lógica do componente vai aqui
  titulo = 'agenda';
}

Repare nos três pedaços importantes do decorador @Component: o selector (a "tag" HTML que representa esse componente, aqui <app-root>), o templateUrl (o arquivo HTML do visual) e o styleUrl (o arquivo CSS). A classe App guarda os dados e a lógica.

Rodar em outra porta ou na rede local

Por padrão o servidor sobe na porta 4200. Você pode mudar a porta ou expor o projeto na rede local (para acessar de outro dispositivo, como o celular) com estes comandos:

# Rodar em outra porta
ng serve --port 4300

# Expor na rede local (acessível pelo IP da máquina)
ng serve --host 0.0.0.0

02 · Componentes e binding

Componentes, templates e data binding

🎯 MISSÃO 02 — FAZER A INTERFACE REAGIR

Você vai criar componentes, exibir dados, responder a cliques, trabalhar com signals e controlar o que aparece na tela.

🎯 Objetivo⏱️ 40 min

O que é um componente

Um componente é o bloco de construção fundamental de uma aplicação Angular. Pense nele como um "pedaço da tela" com comportamento próprio: um menu, um card de contato, um formulário. Cada componente reúne três arquivos: a classe TypeScript (dados e lógica), o template HTML (o que aparece na tela) e o CSS (estilo, isolado daquele componente).

A tela final é uma árvore de componentes: o componente raiz contém outros componentes, que por sua vez contêm outros. Essa composição é o que torna a interface organizada e reutilizável.

Criar um componente

Nunca crie os arquivos na mão — use a CLI, que já gera tudo no padrão certo e registra o componente. Vamos criar um componente chamado contatos:

ng generate component contatos

Pode abreviar para ng g c contatos. A CLI cria uma pasta src/app/contatos/ com quatro arquivos: contatos.ts, contatos.html, contatos.css e um arquivo de teste (contatos.spec.ts).

O arquivo contatos.ts gerado se parece com isto:

import { Component } from '@angular/core';

@Component({
  selector: 'app-contatos',
  imports: [],
  templateUrl: './contatos.html',
  styleUrl: './contatos.css',
})
export class Contatos {

}

Para exibir esse componente dentro do componente raiz, coloque a tag do seu seletor (<app-contatos>) no template app.html e importe o componente na lista imports do app.ts:

// app.ts
import { Component } from '@angular/core';
import { Contatos } from './contatos/contatos';

@Component({
  selector: 'app-root',
  imports: [Contatos],   // componente standalone importado aqui
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
<!-- app.html -->
<h1>Minha Agenda</h1>
<app-contatos></app-contatos>
Componentes standalone
No Angular 17 os componentes já podem ser standalone (e viram padrão a partir do 19): eles se importam diretamente uns aos outros pela propriedade imports, sem precisar de NgModule. Mais em https://angular.dev/guide/components

Interpolação: mostrar dados na tela

A forma mais simples de exibir um dado do componente no template é a interpolação, com chaves duplas {{ }}. Tudo que estiver dentro das chaves é avaliado como uma expressão TypeScript e o resultado aparece na tela.

// contatos.ts
export class Contatos {
  titulo = 'Lista de contatos';
  total = 3;
}
<!-- contatos.html -->
<h2>{{ titulo }}</h2>
<p>Você tem {{ total }} contatos cadastrados.</p>
<p>Ano que vem serão {{ total + 1 }}.</p>

Property binding: passar valores para atributos

Quando você quer definir um atributo ou propriedade de um elemento HTML a partir de um dado do componente, usa colchetes [ ]. Isso é o property binding.

// contatos.ts
export class Contatos {
  urlFoto = 'https://exemplo.com/avatar.png';
  desabilitado = true;
}
<!-- contatos.html -->
<img [src]="urlFoto" alt="Avatar">
<button [disabled]="desabilitado">Salvar</button>

A diferença para a interpolação: com [src]="urlFoto" o valor de urlFoto é atribuído diretamente à propriedade. Escrever src="{{ urlFoto }}" também funcionaria para strings, mas o binding com colchetes é o padrão e funciona para qualquer tipo (booleano, número, objeto).

Event binding: reagir a ações do usuário

Para reagir a eventos (clique, digitação, envio de formulário), usamos parênteses ( ). É o event binding. Dentro dos parênteses vai o nome do evento e o valor é o método a ser chamado.

// contatos.ts
export class Contatos {
  saudar() {
    alert('Olá!');
  }
}
<!-- contatos.html -->
<button (click)="saudar()">Clique aqui</button>

Resumindo os três símbolos, que são a base de tudo em Angular:

SintaxeNomeDireçãoUso típico
{{ }}InterpolaçãoComponente → TelaMostrar texto
[ ]Property bindingComponente → TelaDefinir atributo/propriedade
( )Event bindingTela → ComponenteReagir a eventos

Signals: o jeito moderno de guardar estado

Um signal é um "valor reativo": um contêiner para um dado que, quando muda, avisa automaticamente a tela para se atualizar. Signals são a forma recomendada de guardar estado no Angular moderno (a chamada era signal-first). Para usar, importe signal de @angular/core.

// contatos.ts
import { Component, signal } from '@angular/core';

@Component({ /* ... */ })
export class Contatos {
  // cria um signal com valor inicial 0
  contador = signal(0);

  incrementar() {
    // .update() muda o valor com base no valor anterior
    this.contador.update(v => v + 1);
  }

  zerar() {
    // .set() define um novo valor diretamente
    this.contador.set(0);
  }
}

No template, para ler o valor de um signal, você o chama como uma função (com parênteses):

<!-- contatos.html -->
<p>Contador: {{ contador() }}</p>
<button (click)="incrementar()">+1</button>
<button (click)="zerar()">Zerar</button>
Detalhe que confunde iniciantes: no template, signal se lê com parênteses — contador(), e não contador. Um valor "comum" (não-signal) se lê sem parênteses. Esquecer o () em um signal é um dos erros mais frequentes de quem está começando.

computed: valores derivados

Muitas vezes você precisa de um valor que depende de outro. Para isso existe o computed: ele cria um signal calculado que se atualiza sozinho quando os signals de que depende mudam.

import { signal, computed } from '@angular/core';

export class Contatos {
  preco = signal(100);
  quantidade = signal(2);

  // recalcula automaticamente quando preco ou quantidade mudam
  total = computed(() => this.preco() * this.quantidade());
}
Documentação
Guia completo de Signals: https://angular.dev/guide/signals

Two-way binding: input ligado a um dado

O two-way binding (mão dupla) mantém um campo de formulário e um dado sempre sincronizados: se o usuário digita, o dado muda; se o dado muda no código, o campo atualiza. A sintaxe é [( )] (colchetes com parênteses, apelidada de "banana in a box"). Para campos comuns, usa-se ngModel, que exige importar o FormsModule.

// contatos.ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-contatos',
  imports: [FormsModule],   // necessário para o ngModel
  templateUrl: './contatos.html',
})
export class Contatos {
  nome = '';
}
<!-- contatos.html -->
<input [(ngModel)]="nome" placeholder="Digite seu nome">
<p>Olá, {{ nome }}!</p>
Cuidado ao misturar ngModel com signals. Não use [(ngModel)] diretamente em um signal writable — isso quebra o signal em tempo de execução. Para campo ligado a signal, prefira Reactive Forms (capítulo de Formulários) ou faça o binding em uma propriedade comum. Com signals, o padrão two-way próprio é o model(), usado ao criar componentes reutilizáveis.

O novo control flow: @if e @for

Para exibir conteúdo condicionalmente ou repetir uma lista, o Angular moderno usa um control flow embutido no template, com @if, @else e @for. Ele substitui as antigas diretivas *ngIf e *ngFor e não precisa de import nenhum.

@if / @else — condicional

<!-- contatos.html -->
@if (total() > 0) {
  <p>Você tem {{ total() }} contatos.</p>
} @else {
  <p>Nenhum contato cadastrado ainda.</p>
}

@for — repetição

O @for percorre uma lista. Ele exige a cláusula track, que diz ao Angular como identificar cada item (para atualizar a tela com eficiência). Use um campo único como id, ou $index se não houver id.

// contatos.ts
export class Contatos {
  lista = signal([
    { id: 1, nome: 'Ana' },
    { id: 2, nome: 'Bruno' },
    { id: 3, nome: 'Carla' },
  ]);
}
<!-- contatos.html -->
<ul>
  @for (c of lista(); track c.id) {
    <li>{{ c.nome }}</li>
  } @empty {
    <li>Lista vazia.</li>
  }
</ul>

A cláusula opcional @empty mostra um conteúdo quando a lista está vazia — muito útil e prático.

Versões antigas (15/16): se a turma usar uma versão anterior ao control flow novo, o equivalente é <p *ngIf="total > 0"> e <li *ngFor="let c of lista">, importando o CommonModule. O guia adota o padrão novo, que é o recomendado.

03 · Model e Service

Modelo de dados e service

🎯 MISSÃO 03 — SEPARAR TELA E DADOS

Vamos preparar a estrutura que permite transformar a tela em uma aplicação de verdade: model + service + injeção de dependência.

🎯 Objetivo⏱️ 15 min

Antes de construir o CRUD, precisamos de duas coisas: um modelo que descreve como é um contato, e um service que guarda e manipula a lista de contatos.

Criar uma interface (o "model")

Em Angular, o modelo de um dado é normalmente uma interface TypeScript. Ela apenas descreve o formato do objeto: quais campos ele tem e de que tipo. Isso dá autocomplete e evita erros (por exemplo, escrever c.nomee por engano). Crie o arquivo src/app/models/contato.ts:

// models/contato.ts
export interface Contato {
  id: number;
  nome: string;
  email: string;
  telefone: string;
}

A partir de agora, sempre que uma variável for um contato, tipamos com Contato e o editor nos ajuda a não errar os nomes dos campos.

Criar um service

Um service é uma classe que concentra a lógica de dados e regras de negócio, para que os componentes fiquem focados só na tela. É nele que vamos guardar a lista de contatos e os métodos de adicionar, editar e remover. Gere com a CLI:

ng generate service services/contato

Pode abreviar para ng g s services/contato. Isso cria src/app/services/contato.ts com esta base:

import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root',
})
export class ContatoService {

}

O decorador @Injectable({ providedIn: 'root' }) registra o service de forma global: existe uma única instância dele em toda a aplicação (padrão singleton), e qualquer componente pode pedi-la.

Documentação
Services e injeção de dependência: https://angular.dev/guide/di

Injeção de dependência com inject()

Para usar o service dentro de um componente, nós o injetamos. A forma moderna é a função inject(). O Angular cuida de entregar a instância pronta; não precisamos criar o service com new.

// contatos.ts
import { Component, inject } from '@angular/core';
import { ContatoService } from '../services/contato';

@Component({ /* ... */ })
export class Contatos {
  // injeta a instância global do service
  private service = inject(ContatoService);
}
Alternativa (construtor)
Também é possível injetar pelo construtor: constructor(private service: ContatoService) {}. As duas formas funcionam; inject() é a recomendada nas versões recentes.

04 · CRUD em memória

CRUD em memória (o coração do curso)

🔥 MISSÃO 04 — CONSTRUIR O CRUD

Este é o marco principal. Você vai criar, listar, editar e excluir contatos sem backend.

🎯 Objetivo⏱️ 55 min

Chegamos à parte central. CRUD é a sigla para as quatro operações básicas com dados: Create (criar), Read (ler/listar), Update (atualizar) e Delete (excluir). Para o minicurso, vamos guardar os dados em memória (num array dentro do service), sem backend. Isso deixa o foco no Angular. No capítulo seguinte mostramos como conectar a uma API REST de verdade.

O service completo com as operações CRUD

Vamos preencher o services/contato.ts. Usamos um signal para a lista, de modo que qualquer tela que a use se atualize sozinha quando ela mudar.

// services/contato.ts
import { Injectable, signal } from '@angular/core';
import { Contato } from '../models/contato';

@Injectable({ providedIn: 'root' })
export class ContatoService {

  // lista de contatos guardada em memória, como signal
  private contatos = signal<Contato[]>([
    { id: 1, nome: 'Ana Souza',  email: 'ana@email.com',   telefone: '44 99999-0001' },
    { id: 2, nome: 'Bruno Lima', email: 'bruno@email.com', telefone: '44 99999-0002' },
  ]);

  // controla o próximo id a ser usado
  private proximoId = 3;

  // READ: devolve o signal para a tela ler (somente leitura)
  listar() {
    return this.contatos.asReadonly();
  }

  // READ por id: busca um único contato
  buscarPorId(id: number): Contato | undefined {
    return this.contatos().find(c => c.id === id);
  }

  // CREATE: adiciona um novo contato
  adicionar(dados: Omit<Contato, 'id'>) {
    const novo: Contato = { id: this.proximoId++, ...dados };
    this.contatos.update(lista => [...lista, novo]);
  }

  // UPDATE: atualiza um contato existente pelo id
  atualizar(atualizado: Contato) {
    this.contatos.update(lista =>
      lista.map(c => c.id === atualizado.id ? atualizado : c)
    );
  }

  // DELETE: remove um contato pelo id
  remover(id: number) {
    this.contatos.update(lista => lista.filter(c => c.id !== id));
  }
}

Repare no padrão dos métodos que alteram a lista: sempre usamos .update() criando um novo array (com [...lista], .map() ou .filter()), em vez de modificar o array existente. Isso é importante para os signals detectarem a mudança corretamente.

OperaçãoMétodoTécnica de array
Createadicionar()espalhar e acrescentar: [...lista, novo]
Readlistar() / buscarPorId()ler o signal / .find()
Updateatualizar().map() trocando o item
Deleteremover().filter() removendo o item

Read: listar os contatos na tela

No componente, injetamos o service e guardamos a lista. Como listar() devolve um signal, podemos lê-lo direto no template.

// contatos.ts
import { Component, inject } from '@angular/core';
import { ContatoService } from '../services/contato';

@Component({
  selector: 'app-contatos',
  imports: [],
  templateUrl: './contatos.html',
  styleUrl: './contatos.css',
})
export class Contatos {
  private service = inject(ContatoService);

  // signal com a lista atual de contatos
  contatos = this.service.listar();

  excluir(id: number) {
    this.service.remover(id);
  }
}
<!-- contatos.html -->
<h2>Contatos</h2>

<table>
  <tr>
    <th>Nome</th><th>E-mail</th><th>Telefone</th><th>Ações</th>
  </tr>

  @for (c of contatos(); track c.id) {
    <tr>
      <td>{{ c.nome }}</td>
      <td>{{ c.email }}</td>
      <td>{{ c.telefone }}</td>
      <td>
        <button (click)="excluir(c.id)">Excluir</button>
      </td>
    </tr>
  } @empty {
    <tr><td colspan="4">Nenhum contato cadastrado.</td></tr>
  }
</table>

Assim que a tela carrega, ela já mostra os dois contatos iniciais do service. E como a lista é um signal, ao excluir um contato a tabela some com ele automaticamente — sem nenhum código extra de atualização.

Create: adicionar um novo contato

Vamos criar um pequeno formulário na mesma tela. Usamos [(ngModel)] em propriedades comuns para capturar o que o usuário digita, e um método que chama adicionar() do service.

// contatos.ts (trechos adicionados)
import { FormsModule } from '@angular/forms';

@Component({
  /* ... */
  imports: [FormsModule],   // habilita o ngModel
})
export class Contatos {
  private service = inject(ContatoService);
  contatos = this.service.listar();

  // campos do formulário
  nome = '';
  email = '';
  telefone = '';

  salvar() {
    // validação simples: nome obrigatório
    if (!this.nome.trim()) return;

    this.service.adicionar({
      nome: this.nome,
      email: this.email,
      telefone: this.telefone,
    });

    // limpa o formulário
    this.nome = '';
    this.email = '';
    this.telefone = '';
  }

  excluir(id: number) {
    this.service.remover(id);
  }
}
<!-- contatos.html (formulário acima da tabela) -->
<h3>Novo contato</h3>
<input [(ngModel)]="nome"     placeholder="Nome">
<input [(ngModel)]="email"    placeholder="E-mail">
<input [(ngModel)]="telefone" placeholder="Telefone">
<button (click)="salvar()">Adicionar</button>

Ao clicar em "Adicionar", o service cria o contato com um novo id e o inclui na lista. A tabela, por reagir ao signal, mostra a nova linha imediatamente.

Update: editar um contato existente

A edição reaproveita o mesmo formulário. A ideia: ao clicar em "Editar" numa linha, carregamos os dados daquele contato nos campos e guardamos o id que está sendo editado. Ao salvar, se houver um id em edição, chamamos atualizar(); caso contrário, adicionar().

// contatos.ts (evoluído para editar também)
export class Contatos {
  private service = inject(ContatoService);
  contatos = this.service.listar();

  nome = '';
  email = '';
  telefone = '';

  // null = criando; número = editando aquele id
  editandoId: number | null = null;

  editar(c: Contato) {
    this.editandoId = c.id;
    this.nome = c.nome;
    this.email = c.email;
    this.telefone = c.telefone;
  }

  salvar() {
    if (!this.nome.trim()) return;

    if (this.editandoId !== null) {
      // UPDATE
      this.service.atualizar({
        id: this.editandoId,
        nome: this.nome,
        email: this.email,
        telefone: this.telefone,
      });
    } else {
      // CREATE
      this.service.adicionar({
        nome: this.nome,
        email: this.email,
        telefone: this.telefone,
      });
    }

    this.limpar();
  }

  limpar() {
    this.editandoId = null;
    this.nome = '';
    this.email = '';
    this.telefone = '';
  }

  excluir(id: number) {
    this.service.remover(id);
  }
}

No template, adicionamos o botão "Editar" em cada linha e um texto que muda o título do formulário conforme o modo:

<!-- contatos.html -->
<h3>@if (editandoId !== null) { Editar contato } @else { Novo contato }</h3>

<input [(ngModel)]="nome"     placeholder="Nome">
<input [(ngModel)]="email"    placeholder="E-mail">
<input [(ngModel)]="telefone" placeholder="Telefone">
<button (click)="salvar()">Salvar</button>
@if (editandoId !== null) {
  <button (click)="limpar()">Cancelar</button>
}

<!-- na tabela, dentro de cada linha: -->
<td>
  <button (click)="editar(c)">Editar</button>
  <button (click)="excluir(c.id)">Excluir</button>
</td>

Delete: excluir um contato

A exclusão já está pronta: o método excluir(id) chama remover() no service, que filtra o array. Uma melhoria comum é pedir confirmação antes:

excluir(id: number) {
  if (confirm('Tem certeza que deseja excluir este contato?')) {
    this.service.remover(id);
  }
}
Marco do curso. Com este capítulo, o CRUD completo está funcionando inteiramente no navegador. É o ponto ideal para pausar, testar tudo ao vivo e tirar dúvidas antes de avançar para roteamento e API. Se o tempo estiver curto, este é um ótimo lugar para encerrar a parte prática obrigatória.

Roteamento

🧭 MISSÃO 05 — TRANSFORMAR UMA TELA EM APLICAÇÃO

Você vai dividir a aplicação em páginas e navegar entre componentes sem recarregar o navegador.

🎯 Objetivo⏱️ 20 min

Até agora tudo estava numa tela só. O roteamento permite ter várias "páginas" (que na verdade são componentes) e navegar entre elas mudando a URL, sem recarregar a aplicação. Um projeto criado com roteamento já vem com o arquivo app.routes.ts e o provideRouter configurado no app.config.ts.

Configurar as rotas

As rotas são uma lista de objetos que associam um caminho (path) a um componente. Vamos supor duas telas: uma inicial e a lista de contatos.

// app.routes.ts
import { Routes } from '@angular/router';
import { Inicio } from './inicio/inicio';
import { Contatos } from './contatos/contatos';

export const routes: Routes = [
  { path: '',         component: Inicio },       // http://localhost:4200/
  { path: 'contatos', component: Contatos },     // .../contatos
];

O provideRouter(routes) que liga tudo já fica no app.config.ts:

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
  ],
};

RouterOutlet e RouterLink

Duas peças fazem a navegação funcionar no template. O <router-outlet> é o "buraco" onde o componente da rota atual é exibido. O routerLink é o atributo usado nos links de navegação (no lugar do href, para não recarregar a página). Ambos vêm do RouterOutlet e RouterLink, que devem ser importados no componente.

// app.ts
import { Component } from '@angular/core';
import { RouterOutlet, RouterLink } from '@angular/router';

@Component({
  selector: 'app-root',
  imports: [RouterOutlet, RouterLink],
  templateUrl: './app.html',
})
export class App {}
<!-- app.html -->
<nav>
  <a routerLink="/">Início</a>
  <a routerLink="/contatos">Contatos</a>
</nav>

<!-- o componente da rota atual aparece aqui -->
<router-outlet></router-outlet>

Parâmetros de rota

Muitas vezes precisamos de uma rota "por id", como /contatos/editar/5. Declaramos o parâmetro com dois-pontos no path e lemos o valor no componente com ActivatedRoute.

// app.routes.ts
{ path: 'contatos/editar/:id', component: ContatoForm },
// dentro do componente ContatoForm
import { inject } from '@angular/core';
import { ActivatedRoute } from '@angular/router';

export class ContatoForm {
  private route = inject(ActivatedRoute);

  constructor() {
    const id = Number(this.route.snapshot.paramMap.get('id'));
    // use o id para buscar o contato no service...
  }
}

06 · API REST

Consumindo uma API REST com HttpClient

🌐 MISSÃO 06 — CONECTAR AO MUNDO REAL

O CRUD deixa de viver apenas na memória e passa a conversar com uma API REST.

🎯 Objetivo⏱️ 20 min

Guardar dados em memória é ótimo para aprender, mas some ao recarregar a página. Numa aplicação real, o service conversa com um backend por HTTP. O Angular oferece o HttpClient para isso. Esta seção é opcional no minicurso — mostre se sobrar tempo.

Dica de API para praticar
Para testar sem escrever backend, use o json-server (cria uma API REST fake a partir de um arquivo JSON) ou a JSONPlaceholder (https://jsonplaceholder.typicode.com), uma API pública de exemplo.

Habilitar o HttpClient

Diferente das versões antigas (que importavam o HttpClientModule), hoje basta registrar o provideHttpClient() nos providers globais, no app.config.ts.

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),   // habilita requisições HTTP
  ],
};

Um service que fala com a API

Injetamos o HttpClient no service e criamos um método para cada verbo HTTP. Cada método devolve um Observable, que representa uma resposta que chegará no futuro (assíncrona).

// services/contato.ts (versão com API)
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Contato } from '../models/contato';

@Injectable({ providedIn: 'root' })
export class ContatoService {
  private http = inject(HttpClient);
  private url = 'http://localhost:3000/contatos';

  // READ (GET) — lista todos
  listar() {
    return this.http.get<Contato[]>(this.url);
  }

  // READ por id (GET)
  buscarPorId(id: number) {
    return this.http.get<Contato>(`${this.url}/${id}`);
  }

  // CREATE (POST)
  adicionar(dados: Omit<Contato, 'id'>) {
    return this.http.post<Contato>(this.url, dados);
  }

  // UPDATE (PUT)
  atualizar(c: Contato) {
    return this.http.put<Contato>(`${this.url}/${c.id}`, c);
  }

  // DELETE
  remover(id: number) {
    return this.http.delete(`${this.url}/${id}`);
  }
}
OperaçãoVerbo HTTPMétodo do HttpClient
CreatePOSThttp.post(url, dados)
ReadGEThttp.get(url)
UpdatePUThttp.put(url, dados)
DeleteDELETEhttp.delete(url)

Consumindo no componente com estados de loading e erro

Como a resposta é assíncrona, precisamos "assinar" (subscribe) o Observable para receber os dados quando chegarem. É boa prática mostrar um indicador de carregamento e tratar erros.

// contatos.ts
import { Component, inject, signal, OnInit } from '@angular/core';
import { ContatoService } from '../services/contato';
import { Contato } from '../models/contato';

@Component({ /* ... */ })
export class Contatos implements OnInit {
  private service = inject(ContatoService);

  contatos = signal<Contato[]>([]);
  carregando = signal(false);
  erro = signal('');

  // ngOnInit roda uma vez quando o componente é criado
  ngOnInit() {
    this.carregar();
  }

  carregar() {
    this.carregando.set(true);
    this.service.listar().subscribe({
      next: (dados) => {
        this.contatos.set(dados);
        this.carregando.set(false);
      },
      error: () => {
        this.erro.set('Não foi possível carregar os contatos.');
        this.carregando.set(false);
      },
    });
  }

  excluir(id: number) {
    this.service.remover(id).subscribe(() => this.carregar());
  }
}
<!-- contatos.html -->
@if (carregando()) {
  <p>Carregando...</p>
} @else if (erro()) {
  <p>{{ erro() }}</p>
} @else {
  <table>
    @for (c of contatos(); track c.id) {
      <tr><td>{{ c.nome }}</td></tr>
    } @empty {
      <tr><td>Nenhum contato.</td></tr>
    }
  </table>
}

httpResource: o jeito novo (Angular 21+)

A partir do Angular 21, existe uma forma mais enxuta de buscar dados que dispensa o subscribe manual e já entrega signals de valor, carregamento e erro: o httpResource(). Ele re-executa a busca automaticamente quando suas entradas (signals) mudam.

import { httpResource } from '@angular/common/http';

export class Contatos {
  // entrega .value(), .isLoading() e .error() como signals
  contatosRes = httpResource<Contato[]>(() => 'http://localhost:3000/contatos');
}
<!-- template -->
@if (contatosRes.isLoading()) {
  <p>Carregando...</p>
} @else {
  @for (c of contatosRes.value(); track c.id) {
    <p>{{ c.nome }}</p>
  }
}

Formulários

📝 MISSÃO 07 — VALIDAR O QUE O USUÁRIO DIGITA

Você vai conhecer Reactive Forms e aprender a impedir dados inválidos de chegarem à lógica da aplicação.

🎯 Objetivo⏱️ 15 min

O Angular oferece duas abordagens para formulários. É bom a turma saber que existem as duas, mesmo que o minicurso use principalmente a primeira.

AbordagemComo funcionaQuando usar
Template-drivenUsa ngModel direto no HTML (o que já fizemos no CRUD).Formulários simples e rápidos.
Reactive FormsDefine a estrutura do formulário no TypeScript, com mais controle e validação.Formulários maiores, com validação e lógica.

Reactive Forms na prática

Nos Reactive Forms, montamos o formulário no código com FormBuilder. Importe o ReactiveFormsModule no componente.

// contato-form.ts
import { Component, inject } from '@angular/core';
import { FormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';

@Component({
  selector: 'app-contato-form',
  imports: [ReactiveFormsModule],
  templateUrl: './contato-form.html',
})
export class ContatoForm {
  private fb = inject(FormBuilder);

  form = this.fb.group({
    nome:     ['', [Validators.required]],
    email:    ['', [Validators.required, Validators.email]],
    telefone: [''],
  });

  salvar() {
    if (this.form.invalid) return;
    console.log(this.form.value);   // { nome, email, telefone }
  }
}
<!-- contato-form.html -->
<form [formGroup]="form" (ngSubmit)="salvar()">
  <input formControlName="nome"     placeholder="Nome">
  <input formControlName="email"    placeholder="E-mail">
  <input formControlName="telefone" placeholder="Telefone">

  @if (form.controls.email.invalid && form.controls.email.touched) {
    <small>Informe um e-mail válido.</small>
  }

  <button type="submit" [disabled]="form.invalid">Salvar</button>
</form>

Pontos principais: o [formGroup] liga o form do TS ao HTML, cada formControlName conecta um input a um campo, e (ngSubmit) dispara o envio. Os Validators verificam regras (obrigatório, e-mail, tamanho mínimo etc.), e podemos desabilitar o botão enquanto o formulário for inválido.

Extras e boas práticas

✨ MISSÃO 08 — POLIR A APLICAÇÃO

Vamos reunir pipes, organização, build e boas práticas para deixar o projeto pronto para evoluir.

🎯 Objetivo⏱️ 10 min

Pipes: formatar valores no template

Um pipe transforma um valor na hora de exibi-lo, sem alterar o dado original. Usa-se o caractere | (barra vertical) no template. O Angular já traz vários pipes prontos.

<!-- deixa o texto em maiúsculas -->
<p>{{ nome | uppercase }}</p>

<!-- formata número como moeda brasileira -->
<p>{{ preco | currency:'BRL' }}</p>

<!-- formata uma data -->
<p>{{ dataCadastro | date:'dd/MM/yyyy' }}</p>

Alguns pipes comuns: uppercase, lowercase, titlecase, currency, date, number, percent e json (ótimo para depurar objetos na tela).

Estrutura de pastas sugerida

Para projetos que crescem, vale organizar por tipo de arquivo. Uma estrutura simples e clara para o nosso exemplo:

src/app/
├── models/
│   └── contato.ts
├── services/
│   └── contato.ts
├── contatos/
│   ├── contatos.ts
│   ├── contatos.html
│   └── contatos.css
├── inicio/
│   └── ...
├── app.ts
├── app.html
├── app.config.ts
└── app.routes.ts

Build de produção

Quando a aplicação estiver pronta para publicar, gere a versão otimizada (minificada) com:

ng build

Os arquivos finais ficam na pasta dist/. São apenas arquivos estáticos (HTML, CSS e JS), que podem ser hospedados em qualquer servidor web, como Netlify, Vercel, Firebase Hosting, GitHub Pages ou um servidor próprio.
